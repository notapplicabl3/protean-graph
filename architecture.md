# PROTEAN — architecture

What is built, where it lives, and why it is shaped this way. The front door is `README.md`; the console's contract is `docs/console-api.md`; the state document, the plan and the design records are kept in the private repository, not here. This file is the layer between the front door and the code: the what/where/why of the running system.

## The idea

PROTEAN is a graph. The jobs below are its nodes, one module each in `src/protean/graph/`; the ring (`loop.py`) walks the edges between them, declared once in the node registry (`graph/graph.py`; § The system graph). The thinker's move is the graph's one model-made routing decision: it fires the one node beyond the required ones; the rest fire by rule.

A thought goes in. A model seat, the **thinker** (the director seat renamed in prose; its key stays `director`), answers each call with exactly one move plus a `state` (where the thought stands in at most five plain sentences, and what is open): `ideas` lays out 3–7 options and waits for the operator; `explore` sends a sandboxed **worker** to try a possibility in a clone, whose branch `explore/<session>/<n>` comes back with an unverified report and is never graded or integrated; `task` plans small units, each with checks a program can run; `ask` asks the operator; `rest` waits for their next thought. For each unit the worker edits a clone on its own branch and commits. A **grader** runs the checks against the committed branch; only the grader can mark a unit passed. Accepted work accumulates on one branch in the workspace, `task/<session>`, which only moves to a verified commit. The brain alone writes the thought record (`thought`, `standing`, `open`, `decided` — from the operator's `think --decide` only — and `moves`) inside `task.json`, rendered to `thought.md`. A session runs until the operator closes it (`close`, 2026-10-20: open questions superseded, held work dropped, `stopped`/`closed`, the record readable and every operation and resume refused): it parks on a question or a wait for a thought, and stops at a dollar or tick ceiling until extended. `main` is never touched; nothing is merged or pushed. That is the whole program (thinking sessions, per their spec in the planning layer; before them a goal ran to `done`).

Three trust levels make it work: the thinker is trusted to think and plan and never touches a file; the worker touches files and is trusted with nothing; the grader judges both and calls no model.

## One session, end to end

1. `protean think "<thought>" [--workspace <clone>]` creates `brain/protean/state/<session>/` (and, with no workspace, a one-commit scratch repo under `brain/protean/workspaces/<session>/`), takes a lock, and starts ticking. A parked session does not block a new one; a live brain refuses a second.
2. Each tick is a walk over the node registry (`graph/graph.py`): it declares each node once, with who fires it (the runtime or the thinker) and its edges, and the loop runs the tick's nodes in the one order the edges give. Every tick has these nodes: repair (finish any pass cut between its two writes, and write the memory line a kill cut off after a rest, once; end the tick if the task is terminal, a question is open or something awaits `approve`); block the units whose needs died; budget (check the ceilings); release a held plan once its branches are admitted (after the ceilings, so an approved plan's reader call is never paid at one; a think that landed meanwhile returns it instead); pick the tick's firing (the first pending unit whose needs are all passed and integrated, else a pending explore: a worker firing either way; with neither, the runtime fires the thinker); hold a retry or an explore for `approve` in `hold` mode; then the thinker or the worker; block again; save (count the tick). A worker unit brings the grader, the gate (the weakening check) and the ref move, in that order. The thinker's move fires one node: `task` and `explore` fire the worker, which waits in the queue for a later tick, one per tick; `ask` and `ideas` fire the console and `rest` fires rest, in the thinker's own tick, after it, and a rest brings memory's line. A node can end the tick: then nothing after it runs, save included. Each tick logs its firing set and the order it walked (a `fired` event), and `task.json` keeps the latest. A session awaiting a thought (after `ideas` or `rest`) calls nothing until a `think` lands.
3. The thinker's reply is exactly one move plus `state`: `ideas`, `explore`, `task` (units), `ask` or `rest`. A `standing` byte-identical to the last accepted move's is no progress: returned once, then a runtime `no_progress` question holds every paid call until `yes`. A unit whose predicates name `parents` proposes a branch: the gate hands the parents, the children and the director's rationale to a fresh **reader** call, directly, never through the director; a refusal returns to the director as an error, an admission lets the unit run, and at its integration the parents leave the re-check set for good. A malformed reply is retried once with the errors, then parks the task. A reply whose receipt confirms the call hit its dollar cap (`subtype: error_max_budget_usd`) is a **ceiling**, not a malformed plan: no retry on that input, a `ceiling` log event names the effective cap and which constraint bound it (the per-call limit or the task's remaining budget), and the task parks on a `runtime:` question that only `resume --extend` releases — an extension widens the task budget, never the per-call cap.
4. The worker runs in a fresh clone with no remote, on `unit/<task>/<unit>` branched from the accepted tip, under a kernel sandbox. It ends with its own `exit_code: N` line. The branch is fetched back to the workspace (`--no-tags`), and the candidate, what changed and whether it extends the tip are read there, never in the editor's clone.
5. Grading happens only when the worker reported `exit_code: 0` and the branch carries a change. Every predicate of the unit is checked in the grading clone, a fresh clone of the workspace at the candidate that is removed afterwards (never the editor's own clone, whose `.git` and ignored files the editor wrote), then every accepted unit's retained predicates are re-checked in that same grading clone; a parent whose children all passed on this candidate is excused from that re-check, not graded. When those free checks pass and the candidate touched a `protected` path of an accepted retained `command`, one reader call reads the hunks and says whether the checks got weaker; weakened, or no verdict, rejects the attempt like a failed predicate. All pass → the unit is `passed` with its candidate commit, then `task/<task>` moves to it and the unit is `integrated`. Any failure → the attempt is rejected with notes; two rejections → `failed`, and dependents become `blocked`.
6. A question (the thinker's `ask`, or the runtime's — unknown spend, a cap hit, a reply invalid twice, no progress) is recorded in `task.json` (`questions`: id, asker, reason, status, answer, actor) and emitted on the console; the brain WAITS at the tick boundary for `answer` (routed to the asker only — a runtime answer never reaches a director message), `extend` or `stop`. With no client attached for `unattended_seconds` it fires one macOS notification and parks `interrupted`, exit 12; `protean ctl answer` works offline against `task.json` and `protean resume` continues the session (the thinker's next call is fresh, on the record).
7. An explore runs through the same worker seat in a fresh clone at the accepted tip, under the same sandbox and cap; its branch is fetched back, its report (the tail of the worker's output) is stored on the move labelled unverified, and nothing grades, retries or integrates it. There is no `done`: `rest` records the move and the session waits for a thought.

Exit codes: parked 12 (`interrupted`: a question, a held progression or a wait for a thought, no client attached), stopped 11 (a ceiling, `--abandon`, the console's `close`), the console's `stop`, Ctrl-C or a signal during the drive 130 (the record parks `interrupted` as an unattended park does; 2026-10-23), a usage error or a refusal 2.

Model calls exist in exactly three places, `graph/director.py`, `graph/worker.py` and `graph/reader.py`, through `runner.py`. Everything else is deterministic.

Saved history is a read-only view of the session files. Capabilities advertise request IDs, history pages, offset streams and walk IDs. A think or answer with an ID records its operation and reply in the canonical task save; replay returns that reply without applying the operation again. A failed event append is repaired from that ledger on replay or reload. `thought.md` is written before the canonical `task.json` commit. Each walk has an identity separate from the completed tick count. See the request and history sections of `docs/console-api.md`.

## The invariants that make a pass trustworthy

The old tree's `passed` could not be trusted (three reproduced false-success paths). Every rule below exists because a run or a review showed its absence let a false pass through.

- An ungradeable predicate counts against the unit, never for it. A unit with no predicates never passes. Only the grader sets `passed`.
- File predicates read the branch's committed tree objects, not the working directory, with a size bound and realpath confinement. Symlinks, ignored paths, nested repositories and files a check command wrote are missing or ungradeable.
- An unchanged branch is undelivered: a predicate satisfied by pre-existing files cannot pass a unit.
- The worker's own closing line gates grading: nonzero or missing means nothing is graded. Zero admits the candidate to verification and proves nothing.
- Grading, re-checks and the weakening diff run in the grading clone, a fresh clone of the workspace at the candidate; the brain never trusts the editor's `.git` (a replace ref, a graft, an fsmonitor or clean filter in its config, an ignored `.venv` file), every brain-side git command runs with the fsmonitor off, replace objects ignored and no system config, and `git status` in an editor-written repository runs inside the check-command sandbox. After the check commands the grading clone must be clean and still on the candidate, or the grade is void.
- A candidate must extend the accepted tip; it is rejected if it drops it or breaks any accepted unit's retained predicate (`broke <unit> <pid>`).
- A pass is two durable writes; a tick or resume repairs a pass cut between them without a model call. A rest's memory line, owed to the project's memory and cut off by a kill before the memory node, is written once by the next repair. `task/<id>` moves by a checked `update-ref`; a ref moved from outside parks the task on a question.
- Needs are validated at decode: no self-need, no unknown unit, no cycle, no need on a unit that predates the accepted branch. File-predicate paths are validated at decode with the grader's own confinement rule (`grade.confined`: relative, inside the tree after realpath, not `.git`, no `..` escape) — an invalid path is a correctable decode error returned to the director, never a paid worker call; the grader applies the same rule at grading, so an absolute path or a symlink escape is ungradeable there too.

## Containment and money

- The **worker** runs under `sandbox-exec`: writes denied everywhere except the clone, uv's caches, the temp dirs and `/dev`; fail-closed if the binary is missing; network open (a documented limitation: one profile covers the model call and its children). Tool grant: Read, Edit, Write, Grep, Glob, `uv`, and `git status/diff/add/commit/checkout/branch/rm` — `Bash(uv:*)` admits `uv run sh -c …`, so the grant is a general shell in practice and containment rests on the kernel sandbox alone, never on the grant. Permission mode "don't ask", so anything outside the grant simply fails. `~/.claude` is outside its trees; the CLI tolerates that.
- The **check command** runs under the same profile plus network denied; the worker's, the reader's and the check command's profiles all deny reading the task's `console.json` and the root's `state/lobby.json` (the two tokens — the lobby's starts paid sessions), by name and by the private temp names they are written through, proven on the real binary (audit 2026-10-23, B1 and C3).
- Every model call: `claude -p --setting-sources "" --strict-mcp-config --mcp-config '{"mcpServers":{}}' --model <the seat's pinned model, `config.json` `director_model` / `worker_model` / `reader_model`, default claude-opus-5>`; the director with `--output-format json`, the editor with `--output-format stream-json --verbose` so its transcript streams to the console line by line (`state/<task>/transcript.jsonl`, never `task.json` or a director message) and its receipt is the final `result` event. The director's tools are restricted with `--tools`; `--allowedTools` only pre-approves.
- **Ceilings:** a session's **allowance** starts at `max_usd` and grows by `accrual_usd` per 30 minutes of **active work** (config.json ships $50 and $20 since 2026-10-20, the per-call caps $4 thinker / $8 worker / $3 reader; the code defaults are half those and serve the battery) (`accrual_usd` / `accrual_seconds`; active = wall time the brain spends driving a tick — calls, grading, re-checks — never time waiting at a tick boundary or parked; each tick's time is added to `active_seconds` at its save, a tick cut before its save forfeits it), plus the operator's `extend`s; 100 ticks; $2 per thinker call, $4 per worker call (units and explores), 5 and 15 minute walls, two attempts per unit. Spend reaching the allowance stops the session (`max_usd:` stop reason) in the save that books the crossing call, and `extend` releases it; each call's cap is clipped to the least of its per-call cap and the allowance's left, and under $0.50 of that, no call starts. The reader is the exception (2026-10-20): its spend is booked on the ledger like every call's but never counted against the allowance (`counted_usd` = `cost_usd` less the reader's), and its calls are clipped by its own session budget `reader_max_usd` less what the reader has spent, with no reader call under $0.50 of that (the check holds as a floor-stopped one does; `extend` does not widen it). Cost is summed from receipts; the worker and the reader are fresh sessions per call, so their receipts are the call's own, while the thinker's resumed receipt (`claude -p --resume`, within a warm stretch) reports the whole session's spend and tokens, so the call is charged and recorded what it added over the session's latest earlier receipt (`budget.session_before`); a call with no receipt is charged its cap; an interrupted call books its spend before the signal propagates; a hard-killed call is recorded `pending` before launch and `resume` books it once at its reserved cap and marks the actual spend `UNKNOWN`. (This rule replaced a per-sitting cap.)

## Task size

There are no size classes. Nothing classifies a thought or a task move as small, medium or complex, and no cap, prompt or code path changes with size; a one-line fix and a multi-module feature enter the same loop under the same ceilings. Size exists only as consequences.

- **Where size is decided.** Once, by the thinker, at the unit level inside a `task` move: the prompt asks for units "small enough for one worker call (a few files, one check)" and gives no other rule. The thinker may plan incrementally — a first `task` move of a few units, more moves after they land — or lay the whole plan in one move; nothing in the runtime prefers either.
- **How a wrong size surfaces.** By failure, after the money is spent. A unit too large for one worker call fails its attempt, fails again, comes back `failed`, and the thinker is told to give its work again smaller in a new task, explore what stopped it, or ask the operator. An explore that runs long simply hits the worker's cap and lands as `lost`/`failed` on its move. A thought too large for one session surfaces as a ceiling stop.
- **What varies with size.** Units and the depth of their `needs`; moves; ticks — each thinker call and each worker call (unit or explore) is one tick, so a session's tick count is its moves plus its worker calls plus retries and questions; dollars — a thinker call on a warm cache costs about $0.25, a call that re-writes the whole resumed context (after an hour's wait, or when the CLI injects a tool roster) $2 to $3 at a 280k-token context; the allowance ($25 + $10 per 30 min of active work) binds when spend outruns active time, and 100 ticks bind a long session.
- **What the ceilings mean in practice.** $25 plus accrual and 100 ticks per session: at measured prices (a thinker call about $2, a worker call up to $4) the base buys roughly eight to twelve moves, and half an hour of active work adds about three more; a session that mostly waits for the operator accrues nothing. Measured cost per move from a live thinking session is owed before these numbers are trusted.
- **Where a large thought breaks.** The fixed ceiling (one shape for every size); the record's growth (a fresh thinker call's context is the record, which grows with every move; within a warm stretch the resumed session grows by each message and reply; the operator's `close` is the reset: a new session starts on a fresh record); serial workers; the absence of any carry between sessions beyond `task/<session>` and the thought record. None of these is a size mechanism failing — there is none; they are the costs of one shape.

A sizing step, if one is ever wanted, has a natural home at the gate (admission: is this thought one session?) and would be a design item in the graph design record, not a fact of this file.

## The graph

PROTEAN is a graph in three senses, named in the graph design pass.

- **The system graph:** the parts above are nodes, and the edges between them are declared once in the node registry (`graph/graph.py`), which the loop walks each tick: the edges, not a list, give the order, and two nodes of one tick that no edge orders are refused. The thinker fires the worker, the console or rest, one firing per move; the runtime fires every other node, and the thinker can neither fire, skip nor reorder one. Present: director (cortex), worker, grader, budget, console (brain side; the mailbox it replaced is gone), runtime, and the gate (a name for the admission checks spread across decode, scheduler and budget). Absent by contract, with triggers: thalamus (what the director is shown) and hippocampus (memory across tasks on one workspace).
- **The work graph:** units and their `needs` inside a task. The scheduler, not list order, decides what runs; a dead need blocks its dependents transitively. Built and proven live.
- **The memory graph:** its smallest form exists: the brain's long-term memory (`graph/memory.py`), one line per session rest or close per project, handed to later sessions on that project as the thinker's `memory`. No search, no store beyond the file, no model summarising it; the goal-mode task logs persist unread.

The contracts, the rejected alternatives, and the ordered list of builds they imply are in the graph design record. None of those builds is authorized.

## Why this shape

- **Rewrite, not carving.** The old six-node ring (the retired tree, kept at its tag in the history and exported as `graph/` in the public mirror) was ~23k lines whose completion signal was untrustworthy. It was ruled "too much code and doctrine for a relatively simple idea". The loop kept the two steps that mattered, plan and verify, and dropped the ring, the semantic store, torn-tick replay, learning and the oracle.
- **Expansion only from observed need.** Every addition since (dependencies, the accepted branch, the exit gate, `git rm`, the sandbox) came from a live run showing a gap, and landed with its repro test first, one fresh review after.
- **Serial by design.** One worker per tick. Parallel work waits on budget reservation.
- **Two memories.** The brain owns the long-term memory: the thought record (`task.json`, rendered `thought.md`) is what a session is, and what a fresh thinker call is handed whole. The thinking session owns the short-term memory: the thinker's own CLI session, with its reasoning and its reads, resumed (`--resume`) while the stretch is warm — the last thinker call under an hour ago, the prompt cache's life (`director.warm`, `STRETCH_SECONDS`) — and dropped after a rest, an ask or any longer wait, when the next call starts fresh on the record. The operator's ruling, 2026-10-22. Measured on the first thinking session, before the rule: a cold resume re-wrote a 280k-token context for $2–3 a call and carried the CLI's injected MCP roster (now off for every seat); warm resumed calls cost about $0.25, a fresh call about $0.36. A resumed receipt reports the whole session; the brain books the difference (`budget.session_before`). The long-term half across sessions is `graph/memory.py`: at each rest and close the brain appends the record's distillate to the project's memory file, and a later session on the project is handed the newest five sessions' latest lines as `memory`, the brain writing and the thinker only reading. A thalamus is built only on demonstrated pressure.
- **The battery is the oracle.** `uv run pytest` runs with a shim proving no model call (bound 120 s by pytest's reported time since 2026-10-26, 90 s before; the measured figure lives in `docs/STATE.md`); `protean dry <scenario>` replays ten scripted runs, and `--serve` serves one for a console client. Every change is checked against it.

## Proven live, proven dry, unproven

- **Live** (receipts of the six goal-mode runs, kept privately): `done` on a real goal; a question, an answer, a resume in a new process on the same session; three units with needs running in dependency order with the accepted branch advancing; a failed attempt, a unit rejected for breaking a retained predicate, a `blocked` dependent, a descope on a human yes, the director refusing `done` on an unmet goal; a sandboxed editor doing `git rm`, tests and a commit, and its one outside write refused at the kernel.
- **Dry only:** a worker hitting its dollar cap or wall timeout; the director being refused a `Bash` call.
- **Unmeasured:** final-turn overshoot of a call cap; the stateless thinker's cost per move (measured on the resumed seat: 85% cache writes — the user-level MCP roster injected three times, two cold calls after multi-hour waits; the message itself under 7k tokens — which is why the seats now run without MCP servers and the thinker resumes only within a warm stretch).

## Known limits

All check commands of one candidate share one grading clone, so the unit's own check could plant something (a `.venv` `.pth`, a forged loose object, a skip-worktree bit) that a later re-check in the same pass reads; closing it would mean a clone per check or re-checks before the unit's own commands. A recorded known limit, kept as built until a run shows it matters. No sizing: one loop, one ceiling, every thought; a thought larger than one session is split by hand with nothing carried between sessions (§ Task size). Open worker networking.
