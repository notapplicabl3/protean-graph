# Console API — the brain side

The wire contract every console client builds against: the terminal (`protean ctl`), a native client, an MCP plug-in if one is built. The framing is frozen; the thinking sessions changed operations and fields inside it, never the framing. Code: `src/protean/graph/console.py`; executable form: `tests/protean/test_console.py` and `tests/protean/test_think.py`.

## Finding and reaching the brain

- One console per live session, served by a thread inside `protean think` / `protean resume`. No live brain, no console.
- Listens on `127.0.0.1` only, on an ephemeral port. Never another interface.
- `brain/protean/state/current` names the current session (a new `protean think` or a `protean resume <session>` moves it). `brain/protean/state/<task>/console.json` (mode 0600, removed when the brain exits) holds `{"host": "127.0.0.1", "port": N, "token": "...", "pid": N, "task": "<task>"}`, `<task>` being the session's id. Neither the editor's sandbox nor a check command's (code the editor wrote, run at grading) can read this file.
- Every request carries `Authorization: Bearer <token>`. Without it, or with any other value: `401 {"ok": false, "error": "unauthorized"}`, and nothing changes.
- HTTP/1.0, one request per connection. Bodies are one JSON object, at most 64 KiB.

## Endpoints

| Method | Path | Body | Success |
|---|---|---|---|
| GET | `/snapshot` | none | `200` the snapshot |
| GET | `/stream` | none | `200`, `application/x-ndjson`: line 1 is `{"snapshot": {...}}`, then every `log.jsonl` line appended after the snapshot's `log_bytes` and every `transcript.jsonl` line appended after its `transcript_bytes`, verbatim, one per line (each file in its own order), until the run ends; the last line before EOF is one more `{"snapshot": {...}}`, the terminal state (`terminal` set), since `/snapshot` stops answering as the brain closes |
| POST | `/pause` | `{}` | holds at the next tick boundary; the call in flight finishes |
| POST | `/resume` | `{}` | releases a pause |
| POST | `/stop` | `{}` | answered first, then the Ctrl-C path: the call in flight books its spend, the session saves, the brain exits 130 |
| POST | `/think` | `{"text": "...", "decide": false}` (`decide` may be left out: false) | appended to the thoughts; with `decide: true` also the operator's decision |
| POST | `/answer` | `{"id": "q1", "text": "..."}` | closes that one open question |
| POST | `/extend` | `{"usd": 1.5}`, `{"ticks": 5}` or both | widens the session's ceilings; its dollars raise the allowance |
| POST | `/mode` | `{"mode": "auto"}` or `{"mode": "hold"}` | sets the mode, persisted |
| POST | `/approve` | `{}` | releases the one progression held in `hold` |

An operation answers `200 {"ok": true, "event": {...}}` with the event it logged, or `{"ok": false, "error": "..."}` with: `400` malformed body or field (a `think` without a non-empty `text`, or with a `decide` that is not `true` or `false`, included), `401` no token, `404` no such endpoint or question id, `405` wrong method, `409` the session's state refuses it, `413` body or text too large.

`409` cases: the session was abandoned, or the record ended `done` (runs 1–6 only: a session never ends); `pause` while paused, `resume` while not paused; an `answer` to a question that is not open; an `answer` to a `cap_hit` question (only `extend` releases it); an `answer` other than `yes` to an `unknown_spend` or a `no_progress` question; `mode` naming the mode already in force; `approve` with nothing held, or with the held progression already approved; any operation while the run is ending.

## Snapshot

`task` (the session's id), `thought` (the thought record: `thought` (the operator's seed, verbatim, never edited), `standing` (where it stands, at most five plain sentences, as the thinker's last accepted move put it; `""` before the first), `open` [{`id`, `line`}] (what is still live), `decided` [{`text` (the operator's text verbatim), `created`, `think` (the index from 1 in `thoughts` of the think that said it)}] (the operator's decisions; only a think marked decide adds one, never the thinker)), `workspace`, `project` (the name of the repo the workspace is a clone of, as `protean think` recorded it; `_root` when none was named — a client may show it), `live`, `tick`, `terminal` (null while running; `stopped`, `interrupted`; `done` only on a record of runs 1–6), `stop_reason`, `paused`, `mode` (`auto`, `hold`), `held` (null, or the progression an approve releases: `kind` (`plan`, `retry` or `explore`); for a plan its `units` [{`id`, `intent`, `summary`, `needs`, `predicates` as below}], for a retry `unit` and `attempt`, for an explore `move` and `brief`; plus `approved`, and `thoughts`: how many thoughts the session had when it was held (one more returns it)), `awaiting_thought` (true after an `ideas` or a `rest` move until a think lands), `cost_usd`, `ceilings` (`max_usd` (config, default 25.0) and `max_ticks` (config, default 100), each with every extension; `extra_usd`, `extra_ticks`; `accrued_usd` (what active work has added: `accrual_usd` in config, default 10.0, for every `accrual_seconds`, default 1800, of `active_seconds`, pro rata), `allowance_usd` (what the session may spend, `max_usd` with every extension, plus `accrued_usd`; spend that reaches it, or leaves less than the $0.50 call floor of it, is the `ceiling` stop, and every call's `--max-budget-usd` is clipped to what it has left), `active_seconds` (the wall time the brain has spent driving ticks: thinker, worker, explore and reader calls, grading and re-checks, each tick's added at its save; never a wait at a tick boundary or a park, and a tick cut before its save adds nothing); `director_call_usd` (the thinker's), `worker_call_usd`, `reader_call_usd`, which never widen), `prices` (per seat, `director` (the thinker), `worker`, `reader`, from the model the seat is pinned to: `input`, `output`, `cache_read`, `cache_creation` in USD per million tokens, from `config.json`; null when that model has none pinned. The brain prices nothing with them: a client may price the call in flight from the editor's streamed usage and show it as an estimate until the receipt books it. claude-opus-5's are pinned from Anthropic's price table and proven on run 6's receipts: with the 1-hour cache write at $10, input·5 + output·25 + cache_read·0.5 + cache_creation·10 gives calls c2 ($2.795631) and c3 ($1.82465) to the cent), `units` (the Tasks list: every unit a task move added, with `id`, `intent`, `summary` (the thinker's one plain sentence for the operator beside the editor's `intent`; `""` when it gave none), `status`, `attempts`, `needs`, `integrated`, `predicates` [{`kind`, `args`, and `"retain": false` only on a delivery-only predicate, never re-checked once its unit is accepted; absent means retained; `parents` (`"<unit> <pid>"` ids) only on a child that inherits accepted predicates; `children` only on a parent whose branch was accepted, which is never re-checked again; `protected` (paths relative to the tree) only on a `command` that names them}]), `moves` (the session's moves, oldest first, written by the brain only: `id` (`m1`, `m2`, and so on), `kind` (`ideas`, `explore`, `task`, `ask`, `rest`), `line` (the move in one line), `cost_usd` (the thinker's call, plus its workers' for an explore or a task), `outcome` (`proposed` for ideas; `asked`, then `answered`, for an ask; `rested` for a rest; an explore's `pending`, `running`, `landed` or `not fetched` (with what was off), `interrupted`, `lost` or `returned`; a task's `held`, `returned` or `refused`, or once its units entered, each one's id and status, as `u-1 passed`), and only the pointers it carries: `branch` (an explore's `explore/<task>/<n>`, a task's `task/<task>`), `units` (a task's unit ids), `question` (an ask's question id), `ideas` [{`id`, `case`, `cost`, `serves`}] (an ideas move's options: a one-line case, a one-line cost to explore it, the open id it serves), `brief` (an explore's brief, whole), `report` with `unverified` (an explore's worker report, and always true beside it: nothing grades an explore)), `questions` (the open ones), `thoughts` (the operator's, in order: `text`, `created`, `actor`), `log_bytes` and `transcript_bytes` (the offsets the stream continues from).

A stream line may repeat a change the snapshot already shows; none is skipped.

## Operations land in state

Each operation is checked, recorded in `task.json`, and logged with `actor: "console"`. The loop acts on it at the tick boundary; no operation reaches a node.

- **think** — the thinker's every later message carries every thought, in order (`"thoughts": [...]`), beside the thought record; it reads each as direction, an answer, a possibility or a decision, and the latest wins on conflict. A think ends a wait for a thought (`awaiting_thought` false) and reaches the thinker at its next call; units already in the session run first. A think that lands while a thinker call runs is in no message yet: when that call's move is an `ideas` or a `rest`, the session does not wait for another thought, and the next call carries it. A think changes no ceiling and starts nothing about money. With `"decide": true` it is also the operator's decision: in the same save, live or offline, `decided` gains their text verbatim (as the thought holds it), its time and the think's index. That is the only way an entry enters `decided`; the thinker never writes it, and a reply that carries it is a decode error.
- **answer** — binds to one id, once. The thinker's own question (an `ask` move) is answered in its next message's `answer`, once. A runtime question's answer stays with the runtime, which acts on it, and never reaches the thinker.
- **extend** — adds dollars and/or ticks to the session's ceilings, live, with no upper wall; its dollars raise the allowance by as much. Each press logs its amount, the resulting ceilings and the resulting allowance. It never changes a per-call cap. It releases an open `cap_hit` question and lifts a ceiling stop it clears, spend that reached the allowance included. It is the only operation that changes a ceiling; besides it, only active work grows the allowance (`accrued_usd`), by that rule.
- **mode** — `auto` (default; a record without the field loads as `auto`): the session progresses on its own unless paused. `hold`: exactly three progressions wait at the tick boundary for `approve` — dispatching a `task` move's plan (its units stay outside the session until released), a retry attempt (attempt 2 or later), and an explore (before its worker call). The accepted-ref move (`integrated`) and the thinker's own call are never held. Switching to `auto` releases whatever is held (`approved` with `by: "mode"`).
- **approve** — releases exactly the one held progression (`approved` with `by: "approve"`): a plan's units enter the session, the retry runs, or the explore runs.
- **think while something is held** — returns it to the thinker (`returned`, with a `to_director` note) and the thinker moves again with every thought: a held plan is dropped and none of its units enter the session; a held explore never runs; a held retry does not run and its unit becomes `failed` as it stands (its work comes back as a new task, smaller, or an explore of what stopped it). A think wins over an `approve` the loop has not yet acted on.

## Waits and the unattended park

An open question, a pause, a ceiling stop, a progression held for `approve`, or a wait for a thought (after an `ideas` or a `rest` move) holds the loop at the tick boundary. A wait is not a tick: nothing is spent while it lasts, and it adds no active time.

While a client holds `/stream` open, the brain waits indefinitely. With none attached, every wait but a pause fires one macOS notification. If no client attaches within the unattended timeout (30 minutes, the session's default), the brain parks: a question, a held progression or a wait for a thought leaves the session `interrupted` (exit 12; the held one stays in `task.json`), and a ceiling stop leaves it `stopped` (exit 11). `protean resume` continues the session. A pause never parks.

## No live brain

`protean ctl answer`, `think`, `extend`, `mode` and `approve` write straight into the parked session's `task.json` (their events carry `"live": false`); `protean resume` then continues. `pause`, `resume` and `stop` need a live brain and are refused. `protean resume --extend N|$X` is kept as a thin alias: one `extend`, then resume.

Terminal client: `protean ctl pause | resume | stop | think <text> [--decide] | answer <id> <text> | extend <N|$X>... | mode auto|hold | approve | snapshot | watch`, each on the current session. `watch` prints the snapshot, then the stream, and counts as an attached client. `protean think "<thought>" [--workspace <clone>] [--mode auto|hold] [--project <name>]` starts a session (default `auto`; in `hold` even its first `task` move's plan waits for `approve`); with no `--workspace` its tree is a fresh git repository with one empty commit under `brain/protean/workspaces/<session>/`. A new `protean think` while another session is parked (awaiting a thought, or interrupted on a question) is not refused: `current` moves to the new session and the old one stays as it was; a live brain (its lock held) refuses a second, and refuses a `protean resume` of another session. `protean resume [<session>]` wakes the named session, which becomes the current one, or the current one when none is named; `--abandon` closes it for good. `protean run` is no verb any more (nonzero exit, as any unknown verb). `protean status` prints the thought record (the thought, standing, open, decided and the moves), the units, the thoughts, the budget, the mode and what is held.

## The editor's transcript

The editor is launched with `claude -p --output-format stream-json --verbose` (the CLI refuses `stream-json` without `--verbose`); the thinker keeps `--output-format json`. Its stdout is read line by line as it runs, a task unit's and an explore's alike, and each line is appended to `state/<task>/transcript.jsonl` as one `transcript` event, which the stream carries during the call. The transcript is a console field only: it is never in `task.json`, the log or a thinker message, and nothing in it counts toward a verdict. The receipt is the stream's final `result` event (cost, usage, session, subtype, result), read the way the single `json` blob was.

## Branch admission

A `task` move's unit whose predicates carry `parents` proposes a branch: those accepted predicates hand their promise to the unit's children. Before the unit enters the session, inside the same tick, the brain makes one fresh `reader` call (seat `reader`, its own `call` event, charged to the session, capped at `reader_call_usd`) and logs `branch_admitted` or `branch_refused`. Only a reader `yes` admits; a `no`, or any call that fails, reaches its cap or answers anything else, refuses, and the whole plan goes back to the thinker as one line (`unit 'u-3': branch refused by the reader: <note>`). A reader call that times out or leaves no receipt refuses nothing: its cap is booked, paid work holds on an `unknown_spend` question, and the plan is `held` unadmitted; `yes` releases it and the reader is asked again. The thinker never sees the reader's input, transcript or receipt. Admission is decided once per plan, by the mode its thinker call started in: from `auto` inside the call, from `hold` after `approve` (an admitted plan is `approved`, a refused one is dropped). A branching plan whose call started in `hold` is `held` for its admission even when `auto` landed during the call (released with `by: "mode"` once admitted); a plan admitted inside its call is never asked again, whatever the mode became. A held plan is released only after the ceilings: at a ceiling, or under the call floor (also between two of its admission calls), it stays held and approved, nothing is refused, until `extend`; a think that lands during its admission call returns it (`returned`) and none of its units enter. The parents stay in the re-check set until the branching unit is integrated (`branch_accepted`), except on that unit's own candidate: once every child passes there, the parents of those children are not graded and its `verdict` records each as `excused` with the `children` that carry it, so the unit may rename or remove what they pinned and no parent is a `broke` there (any other accepted predicate is re-checked as always). A child that fails rejects the candidate on its own grade and the parents hold untouched; nothing about a branch asks the operator.

## The weakening check

Every retained `command` predicate names `protected` paths: the files and directories that control its result (its tests, their config), relative to the tree; a directory covers everything under it (`tests` covers `tests/test_x.py`, never `tests_old.py`). A plan whose retained command names none, or names one outside the tree, goes back to the thinker at decode; a delivery-only command may omit them. Before a candidate integrates, and only once it has passed every free check (its own grade, the re-checks, the clean clone), the gate diffs it against the accepted tip it branched from (renames count as a deletion and an addition). The protected set is the union over every integrated unit's command still in the re-check set, less the parents excused on this candidate; the candidate's own commands never count. No protected path touched: no call, and the `verdict` records `weakening` with `result: "untouched"`. Touched: exactly one fresh `reader` call (seat `reader`, its own `call` event, charged to the session, capped at `reader_call_usd`) in a clone at the candidate, given the unit's intent, the touched paths, the accepted commands they control and their hunks (cut at 16,000 characters with a marker), and one `weakening` event. The reader answers `{"verdict": "yes"|"no", "kind": "<kind>", "note": "<one line>"}`, `yes` meaning weakened, kind one of `deleted tests`, `weakened assertions`, `skipped or expected-fail`, `legitimate refactor`, `strengthened`, `unrelated`. `no` integrates as usual. `yes` rejects the attempt like a failed predicate (no integration, the attempt consumed, `failed` after the last): the next attempt's findings carry the touched paths, the kind and the note as evidence. A call that gives no verdict (floor, sandbox, clone, timeout, no receipt, error, cap hit, malformed answer) never integrates: the attempt is rejected with the note `weakening check could not run: <why>`. Nothing about the verdict asks the operator; a timeout or missing receipt does hold paid work on an `unknown_spend` question before the retry.

## Questions

A question in `task.json` (and in the snapshot) has these fields:

- `id`: `q1`, `q2`, and so on, never reused.
- `asker`: `director` (the thinker's seat) or `runtime`.
- `reason`: `question` for the thinker (its `ask` move); `invalid_plan`, `no_progress`, `stale_tip`, `cap_hit` or `unknown_spend` for the runtime. `invalid_plan` opens when the thinker's reply was invalid twice. `no_progress` opens when a second reply in a row left the standing unchanged (the first went back to the thinker as a `no_progress` note): no paid call starts until `answer <id> yes`, which calls the thinker again; any other answer is refused (`409`), and a thought that lands meanwhile rides in that call while the answer never does. Money opens no question: spend that reaches the allowance (`ceilings.allowance_usd`) is the `ceiling` stop (`terminal` `stopped`, `stop_reason` `max_usd: …`), set in the same save that books the thinker's, a worker's or an explore's call that reached it (a reader's call is booked in the gate's own save, and the stop follows before any further call), and before a call would start with less than the $0.50 call floor left: no paid call starts until `extend` adds dollars, or the session's own active time, counted at the end of the tick that reached it, clears it (`released`). `unknown_spend` opens in the same save that books any call ending without a receipt (timed out, no receipt, interrupted by Ctrl-C or `stop`, or lost to a kill): its reserved cap is charged, `actual_usd` is `"UNKNOWN"`, and no paid call starts until `answer <id> yes` (before it, only a kill held).
- `text`, `created`, `status` (`open`, `answered`, `superseded`), `answer`.
- `actor`: who answered (`console`).
- `disposition`: what the runtime did. `delivered` for the thinker's; `continued`, `extended` or `retried` for the runtime; `abandoned` or `repaired` when superseded. A record of runs 1–6 loads read-only and may carry reasons and dispositions this page no longer lists.
- `context`: what the runtime acts on, such as the call ids or the unit a stale tip names.

## Events on the stream

Every line has `ts` (UTC, ISO seconds) and `event`. `to_director` marks a note the thinker's next message carries (the key keeps the seat's name, as `director_call_usd` does); no runtime question or answer event has one.
