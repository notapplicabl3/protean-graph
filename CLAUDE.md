# PROTEAN

A graph of nodes around Claude Code, walked by a ring: a **thinker** seat moves a thought forward one move at a time (ideas, explore, task, ask, rest) and so, through its move, picks which thinker-fireable node fires next (version one: exactly one firing per reply — `worker`, `console` or `rest` — derived from the move; the registry guard bites only once `fire` is on the wire); a contained **worker** does each unit or explore in a clone; a **grader** verifies units; a **reader** admits a branch of retained predicates or judges a weakening; **budget** holds every ceiling; a **console** (a local API inside the brain, `protean ctl …` in the terminal) carries the operator's thoughts, answers, approvals and extensions; **memory** keeps one line per session on a project. The nodes live one module each in `src/protean/graph/`; the ring (`src/protean/loop.py`) walks the edges, declared once in the node registry `src/protean/graph/graph.py` (`architecture.md` § The system graph). The shape: the thinker fires the one node beyond the required ones — worker, console or rest, one firing per move — and the runtime fires the rest; the registry rides the console snapshot as `graph`. Sessions are thinking sessions; there is no goal mode and no `done`. `README.md` says how to run it and what this public mirror leaves out; `architecture.md` is the what/where/why of the running system.

Rules:

- Every model call goes through a `Runner`; tests inject scripted runners and the shim on PATH fails any test that reaches the real binary.
- Only `grade.grade()` sets a unit `passed`. A director reply never carries a status. An ungradeable predicate never passes. A unit whose branch carries no change delivered nothing and is ungradeable, so a predicate satisfied by pre-existing files cannot pass. `file_exists` and `file_contains` read the branch's tree objects, never the working tree: only a committed regular file counts, and a symlink, a directory, a nested repository, an ignored path or anything under `.git` never does.
- A unit's `needs` must pass and be integrated before it runs; a need that fails makes its dependents `blocked`. Decode rejects an unknown need, a self-need and a cycle.
- `task/<task>` in the workspace is the accepted work: every unit branches from its tip, and it moves only by a checked `update-ref` fast-forward to a candidate that passed its own predicates and every integrated unit's RETAINED `file_exists`, `file_contains` and `command` predicates (`retain` defaults to true; a `retain: false` predicate must pass its own unit's grade and is never re-checked after). A retained predicate leaves the re-check set only by branching: a unit whose predicates name it as a parent is admitted by one fresh reader call, its own candidate is excused from that parent once every child passed (recorded `excused`, never `broke`), and at its integration the parent is retired for good. A retained `command` must name `protected` paths at decode; a candidate that passed every free check and touched one of an accepted command's protected paths is integrated only after one reader call says the checks are not weakened (`weakened` or no verdict rejects the attempt; untouched costs nothing). The grade, the re-checks and the weakening diff run in the grading clone, a fresh clone of the workspace at the candidate, never in the editor's clone, and count only if that clone still sits clean on the candidate afterwards (a check command that moves HEAD or leaves a file fails the attempt). Branch admission is decided once per plan, by the mode its director call started in. A pass saves `passed` + `candidate` first, then moves the ref and saves `integrated`; a tick or resume finishes a cut pass without re-running the worker, and a ref moved outside the loop parks the task on a question instead (`--abandon` still closes it). `main` is never checked out, moved or merged into.
- A `command` predicate runs under `sandbox-exec`: no network, writes only inside the clone, uv's caches and the temp dirs, no read of the task's `console.json` or the root's `state/lobby.json`, by name or by the private temp names they are written through. Without the sandbox binary it is ungradeable; a check command never runs unconfined.
- A model call interrupted mid-flight (Ctrl-C, SIGTERM, SIGHUP or any exception) books its spend on the task and saves before the interruption propagates: the clipped `--max-budget-usd` while the call runs, the receipt's cost once it has returned. On Ctrl-C, SIGTERM, SIGHUP or the console's `stop` — all KeyboardInterrupt — the CLI exits 130 and the record parks `interrupted` with a `parked` event (`hold` `stop`), the mark written on the record as the tick last saved it, never on the loop's in-memory task (so a client tells a stop from a lost brain, and no unit is charged an attempt it never ran); `protean resume` continues the task. Any other exception books the call's spend but leaves `terminal` null — the record reads as a lost brain until a resume — and exits 2 for a refusal or an OS error, else with a traceback. Every call is recorded in `task.json` BEFORE it launches (`Call`: seat, attempt, cap, charge vs receipt cost, tokens, message size, session, outcome); a SIGKILL leaves that record `pending`, and `resume` books it once at its reserved cap, records the actual spend `UNKNOWN`, and parks the task on a `runtime:` question before any further paid call — `yes` continues under the uncertainty. Unavailable measurements are null, never 0.
- A bug fix lands its repro test first. Behaviour a landed test pins changes only with the operator's word.
- Nothing spends without the operator's go. `protean think` and `protean resume` spend on a real workspace.
- `brain/protean/state/` is runtime state, never hand-edited; questions, thoughts, the thought record (`thought.md` is a rendered view of `task.json`, never edited) and the console's port/token file live there. `mode` is `auto` or `hold` per session (`protean ctl mode hold`): hold waits for `protean ctl approve` before a task move's units enter the session, before a retry attempt and before an explore — never before the ref move; a think while something is held returns it to the thinker. After `ideas` or `rest` the session waits for a think. `protean lobby` is the standing console beside the per-session one: it lists every session on the root, serves a parked or ended session's record and documents, and starts or resumes a session for a client by spawning a detached `protean think` or `protean resume` — the only way a client seeds a thought; it never calls a model itself. `protean ctl close` (the app's End session) ends a session for good: open questions superseded, held work dropped, `stopped`/`closed`, the record readable, every later operation and `resume` refused. `decided` is written only by a console think with `--decide`. The editor's transcript streams to the console only. Answer, think and extend through `protean ctl` (live brain or offline against `task.json`), never by editing the file. The editor's, the reader's and a check command's sandboxes deny reading `console.json` and `state/lobby.json`, by name and by temp name; the token never enters a child's env or argv.
- Prose that persists follows ASD-STE100: docs, `README.md`, specs, the seat prompts under `brain/protean/`, strings shown to the operator, commit messages. Code tokens and the operator's quoted words are exempt. Existing text converts when it is edited, never in a bulk rewrite without the operator's order. A seat prompt converts only with the operator's go, because its wording is live behavior.
